# 기능 분류 체계 정의

> folio4me 프로젝트의 기능 분류 기준

---

## 1. 개요

folio4me 프로젝트의 기능은 **서비스 동작 필수성**과 **사용자 경험 기여도**를 기준으로 다음 세 가지 등급으로 분류합니다.

---

## 2. 분류 정의

### 2.1 필수 (Essential)

| 항목 | 내용 |
|:-----|:-----|
| **명칭** | 핵심 기능 |
| **정의** | 이 기능이 없으면 **서비스 자체가 동작하지 않는** 기능 |
| **판단 기준** | "이 기능 없이 사용자가 포트폴리오를 생성할 수 있는가?" → **No** |
| **특징** | 서비스의 존재 이유를 구성하는 기능. 이것이 없으면 MVP조차 성립하지 않음 |

---

### 2.2 공통 (Standard)

| 항목 | 내용 |
|:-----|:-----|
| **명칭** | 기본 기능 |
| **정의** | 없어도 동작은 하지만, **일반적인 웹 프로덕트가 갖추고 있어 부재 시 완성도가 낮아 보이는** 기능 |
| **판단 기준** | "경쟁 서비스 대비 기본기가 부족해 보이는가?" → **Yes** |
| **특징** | 사용자가 당연히 있을 것으로 기대하는 기능. 없으면 "미완성" 또는 "불친절"하다는 인상을 줌 |

---

### 2.3 감동 (Delight)

| 항목 | 내용 |
|:-----|:-----|
| **명칭** | 차별화 기능 |
| **정의** | 일반적인 프로덕트에는 없지만, **우리 서비스만의 고유한 가치로 사용자에게 긍정적 인상을 주는** 기능 |
| **판단 기준** | "이 기능이 사용자의 기대를 초과하는가?" → **Yes** |
| **특징** | 경쟁 서비스와의 차별점. 사용자 만족도와 재방문율에 직접적으로 기여 |

---

## 3. 분류 간 관계

```
┌─────────────────────────────────────────────┐
│              감동 (Delight)                 │  ← 기대 초과, 차별화
├─────────────────────────────────────────────┤
│              공통 (Standard)                │  ← 기대 충족, 기본기
├─────────────────────────────────────────────┤
│              필수 (Essential)               │  ← 서비스 동작 전제
└─────────────────────────────────────────────┘
```

- **필수**가 없으면 서비스가 동작하지 않음
- **공통**이 없으면 서비스가 미완성으로 보임
- **감동**이 없으면 서비스가 평범해 보임

---

## 4. 개발 우선순위 원칙

| 순서 | 원칙 |
|:-----|:-----|
| 1 | **필수 → 공통 → 감동** 순서로 구현 |
| 2 | 필수 기능이 완료되지 않은 상태에서 감동 기능에 리소스를 투입하지 않음 |
| 3 | 공통 기능은 MVP 범위에 포함하되, 초기 버전에서는 최소 수준으로 구현 가능 |
| 4 | 감동 기능은 v1.0 이후 점진적으로 추가 |

---

## 5. 우선순위(P0~P3)와의 연계

| 기능 등급 | 권장 우선순위 | 비고 |
|:----------|:--------------|:-----|
| 필수 (Essential) | P0, P1 | 없으면 서비스 불가 또는 주요 기능 |
| 공통 (Standard) | P1, P2 | 첫 릴리즈 포함 또는 다음 릴리즈 |
| 감동 (Delight) | P2, P3 | 다음 릴리즈 또는 나중에 |
