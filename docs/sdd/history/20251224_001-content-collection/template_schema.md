# Template Schema

> folio4me 포트폴리오 템플릿 스키마 명세서

---

## 1. 개요

이 문서는 포트폴리오 생성에 사용되는 템플릿의 구조와 메타데이터 스키마를 정의합니다.

### 1.1 목적

- 템플릿 디렉토리 구조 표준화
- 메타데이터 스키마 정의로 LLM-as-a-Judge 매칭 지원

### 1.2 관련 문서

- `style-and-generation-talk-flow.md`: 스타일 질의 및 생성 플로우
- `style_data_schema.md`: 스타일 데이터 스키마
- `portfolio-data-schema.md`: 포트폴리오 데이터 스키마

---

## 2. 디렉토리 구조

```
/templates
  ├── 1/
  │   ├── metadata.json       ← 템플릿 메타 정보 (필수)
  │   ├── preview.png         ← 정적 미리보기 이미지 (필수)
  │   ├── preview.gif         ← 동적 미리보기 (선택)
  │   └── src/                ← 템플릿 소스 코드 (필수, 내부 구조는 자유)
  │
  ├── 2/
  │   ├── metadata.json
  │   ├── preview.png
  │   ├── preview.gif
  │   └── src/
  │
  └── {n}/
      └── ...
```

## 3. metadata.json 스키마

### 3.1 필드 정의

| 필드 | 타입 | 필수 | 설명 |
|:-----|:-----|:-----|:-----|
| `id` | number | ✅ | 템플릿 고유 식별자 (디렉토리명과 동일) |
| `title` | string | ✅ | 템플릿 이름 (사용자에게 표시) |
| `description` | string | ✅ | 템플릿 스타일 설명 (LLM 매칭용 키워드 포함) |
| `link` | string | ✅ | 템플릿 원본 출처 URL |

### 3.2 JSON 예시

```json
{
  "id": 1,
  "title": "minimalist-portfolio",
  "description": "어두운 색깔의 깔끔한 스타일",
  "link": "https://v0.app/chat/minimalist-portfolio-cs9qhpwj4ep"
}
```

## 4. 소스 코드 구조 (src/)

### 4.1 규격

- `src/` 디렉토리는 **필수**이며, 내부 구조는 템플릿별로 자유
- **`src/README.md`는 필수** - 추가 작업 안내용
- 템플릿은 **`public/portfolio.json`을 참조**하여 데이터를 렌더링해야 함
- 생성 시 `templates/{id}/src/` → `data/{uuid}/src/`로 복사됨
- 생성 시 `data/{uuid}/*.json` → `data/{uuid}/src/public/`로 복사됨

### 4.2 필수 파일

| 파일 | 필수 | 설명 |
|:-----|:-----|:-----|
| `README.md` | ✅ | 추가 작업 안내 (이미지 등), 사용자에게 표시됨 |
| 기타 | - | 템플릿별 자유 구성 |

### 4.3 README.md 작성 규칙

`src/README.md`는 사용자에게 표시되는 안내 문서입니다. 다음 내용을 **반드시** 포함해야 합니다:

1. **환경 구성 방법** - 의존성 설치 등 초기 설정
2. **실행 방법** - localhost에서 포트폴리오 실행하는 방법
3. **추가 이미지 안내** - 필요한 이미지 파일과 역할

#### 전체 템플릿


### 4.4 데이터 참조

생성 시 `portfolio.json`과 `style.json`이 `src/public/` 폴더로 복사됩니다:

```
data/{uuid}/
├── portfolio.json    ← 원본 포트폴리오 데이터
├── style.json        ← 원본 스타일 데이터
└── src/              ← 템플릿 + 복사된 데이터
    ├── README.md
    ├── public/
    │   ├── portfolio.json  ← 복사됨 (템플릿이 참조)
    │   └── style.json      ← 복사됨
    └── ...
```

**데이터 접근 경로 (통일 규칙):**
- Next.js 템플릿: `/portfolio.json` (public 폴더 규칙)
- 정적 HTML 템플릿: `./public/portfolio.json`

### 4.5 구조 예시

템플릿별로 다양한 구조가 가능합니다:

**예시 1: 정적 HTML**
```
src/
├── README.md         ← 필수
├── public/
│   ├── portfolio.json  ← 복사됨
│   └── style.json      ← 복사됨
├── index.html
├── style.css
└── script.js         ← fetch('./public/portfolio.json')
```

**예시 2: 프레임워크 기반 (Next.js)**
```
src/
├── README.md         ← 필수
├── public/
│   ├── portfolio.json  ← 복사됨
│   └── style.json      ← 복사됨
├── app/
│   └── page.tsx      ← fetch('/portfolio.json') 또는 서버사이드 로드
├── package.json
└── ...
```

## 5. LLM-as-a-Judge 매칭

### 5.1 매칭 프로세스

```
┌─────────────────────────────────────────────────────────────────┐
│  사용자 스타일 입력 (평문)                                       │
│  예: "심플하고 깔끔했으면 좋겠어요. 가독성이 중요해요."           │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│  LLM-as-a-Judge                                                 │
│  • 모든 템플릿의 metadata.json 로드                             │
│  • 사용자 입력 ↔ description 비교                               │
│  • 유사도 점수 산출                                             │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│  최적 템플릿 선정                                               │
│  • 가장 높은 점수의 템플릿 반환                                  │
│  • 사용자에게 preview 표시                                      │
└─────────────────────────────────────────────────────────────────┘
```

### 5.2 description 작성 가이드

LLM 매칭 정확도를 높이기 위한 description 작성 원칙:

1. **구체적 키워드 포함**: "깔끔한", "미니멀한", "개발자스러운" 등 사용자가 사용할 법한 표현
2. **색상/레이아웃 명시**: "모노톤", "여백 활용", "카드 기반" 등
3. **2~3문장 권장**: 너무 짧으면 매칭 정확도 저하, 너무 길면 노이즈 증가

**좋은 예시:**
```
"깔끔하고 미니멀한 디자인. 여백을 활용한 가독성 중심 레이아웃. 
모노톤 색상과 심플한 타이포그래피로 내용에 집중할 수 있는 구조."
```

**나쁜 예시:**
```
"예쁜 디자인"  // 너무 모호
"This is a minimal template with clean design..."  // 영어 사용
```
