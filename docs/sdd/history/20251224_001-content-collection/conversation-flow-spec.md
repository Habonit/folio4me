# Portfolio Conversation Flow Spec

> folio4me 포트폴리오 콘텐츠 수집 대화 흐름 명세서

---

## 1. 개요

이 문서는 사용자로부터 포트폴리오 콘텐츠를 수집하기 위한 대화 흐름을 정의합니다.

### 1.1 목적

- 사용자와 AI 간 대화를 통해 포트폴리오에 필요한 정보를 단계별로 수집
- 일관된 데이터 구조로 저장하여 포트폴리오 생성에 활용

### 1.2 대상 사용자

- 기술 직군 (개발자, AI 엔지니어, MLOps 등)

### 1.3 관련 문서

- `portfolio-data-schema.md`: 본 대화를 통해 수집되는 데이터 스키마
- `style-and-generation-talk-flow.md`: 본 대화 완료 후 진행되는 스타일 선택 흐름
- `development.md`: 전체 개발 단계 정의 (Phase 1)

---

```
├─────────────────────────────────────────────────────────────────┤
```

## 3. Step별 상세 정의

### Step 0. Gate

| 항목 | 내용 |
|:-----|:-----|
| 목적 | 서비스 대상 여부 확인 |
| 질의 | 희망 직무 확인 |
| 분기 | 기술 직군 → Step 1 이동 / 그 외 → 서비스 종료 안내 |

**대화 예시:**
```
[AI] 안녕하세요! 포트폴리오 생성을 도와드리겠습니다.
     본인의 희망 직무는 어떻게 되나요?

[사용자] 백엔드 개발자입니다.

[AI] 백엔드 개발자시군요! 그럼 포트폴리오 작성을 시작하겠습니다.
```

```
[사용자] 마케터입니다.

[AI] 죄송합니다. 현재는 기술 직군(개발자, AI 엔지니어, MLOps 등)을 위한 
     포트폴리오 생성만 지원하고 있습니다. 추후 업데이트 예정입니다.
```

### Step 1. Personal Info

| 항목 | 내용 |
|:-----|:-----|
| 목적 | 기본 개인정보 수집 |
| 필드 | 이름, GitHub 주소, 이메일, 증명사진 |
| 필수 여부 | 필수 |
| 반복 입력 | X |

**대화 예시:**
```
[AI] 기본 개인정보를 입력받겠습니다.
     입력 필드: 이름, GitHub 주소, 이메일
     
     순서대로 입력해주세요.

[사용자] 홍길동, https://github.com/honggildong, hong@example.com

[AI] 입력된 내용:
     • 이름: 홍길동
     • GitHub: https://github.com/honggildong
     • 이메일: hong@example.com
     
     마지막으로 포트폴리오에 사용할 증명사진을 업로드해주세요.

     ⚠️ 주의: 공식적인 사진을 업로드해주세요.
     (예: 정장 사진, 단정한 복장의 증명사진)
     
     부적절한 예시: 여행 사진, 셀카, 과도한 필터 적용 사진, 
     반려동물과 함께 찍은 사진 등

[사용자] (이미지 업로드)

[AI] 증명사진이 등록되었습니다.
     개인정보 입력이 완료되었습니다. 다음은 이력(Work Experience) 정보입니다.
```

### Step 11. About

| 항목 | 내용 |
|:-----|:-----|
| 목적 | 자기소개 3문장 작성 |
| 필수 여부 | 필수 |
| 반복 입력 | X (확인까지 수정 반복) |

**진행 방식:**
1. 지금까지 작성한 내용 요약 제시
2. 사용자가 강조하고 싶은 포인트 입력
3. AI가 3문장 About 초안 생성
4. 사용자 확인까지 수정 반복

**대화 예시:**
```
[AI] 마지막으로 자기소개(About) 3문장을 작성합니다.
     
     지금까지 입력하신 내용을 요약하면:
     • 희망 직무: 백엔드 개발자
     • 주요 기술: Python, FastAPI, Docker
     • 경력: 기원테크 AI 모델 개발 (1년)
     • 대표 프로젝트: folio4me
     
     자기소개에서 특별히 강조하고 싶은 포인트가 있으신가요?
     (예: 협업 능력, 문제 해결력, 특정 도메인 경험 등)

[사용자] AI 서비스 배포 경험과 빠른 학습 능력을 강조하고 싶어요.

[AI] 입력하신 내용을 바탕으로 자기소개 초안을 작성했습니다:
     
     "AI 모델 개발부터 서비스 배포까지 전 과정을 경험한 백엔드 개발자입니다.
     Python과 FastAPI를 활용한 API 설계에 강점이 있으며, 
     새로운 기술을 빠르게 습득하여 실무에 적용하는 것을 즐깁니다."
     
     이대로 확정하시겠습니까?

[사용자] 네, 좋아요.

[AI] 자기소개가 확정되었습니다.
     
     포트폴리오 콘텐츠 수집이 모두 완료되었습니다!
     이제 포트폴리오 스타일을 선택하는 단계로 넘어갑니다.
```

```
[AI] 수정된 자기소개 초안입니다:
     
     "AI 모델 개발부터 서비스 배포까지 전 과정을 경험한 백엔드 개발자입니다.
```

## 4. 공통 입력 패턴

### 4.1 입력 플로우 (Step 2~9 공통)

```
┌─────────────────────────────────────────────────────────────┐
│  1. 기본 필드 안내                                           │
│  2. "OOO이 있으신가요?"                                      │
│     └─ 없음 → 다음 Step 이동                                 │
│     └─ 있음 → 항목 입력 요청                                 │
│  3. 사용자 입력 (고정 필드 순서대로)                          │
│  4. 입력 내용 확인 출력                                      │
│  5. "추가로 더 있으신가요?"                                  │
│     └─ 있음 → 3번으로 반복                                   │
│     └─ 없음 → 다음 Step 이동                                 │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 기간 입력 포맷

- 형식: `YYYYMMDD~YYYYMMDD`
- 예시: `20230301~20231231`
- 현재 진행 중인 경우: `20230301~present`

### 4.3 관련 링크 입력 안내

- 모든 관련 링크 필드는 **여러 개 입력 가능**
- 입력 형식: 쉼표(,)로 구분
- 예시: `https://github.com/..., https://demo.example.com`

## 5. 완성도 검증 로직

### 5.1 개요

각 Step에서 사용자 입력이 완료되었는지 검증하고, 미완성 시 재질문을 통해 누락된 필드를 수집합니다. 검증은 **항목 레벨**과 **단계 레벨** 두 단계로 진행됩니다.

### 5.2 confirmed 필드

- 모든 항목에 `confirmed` 필드 존재 (기본값: `false`)
- 항목의 모든 필수 필드가 채워지면 `confirmed: true`로 변경
- 단계(Step)의 모든 항목이 `confirmed: true`일 때 다음 단계로 이동 가능

### 5.3 검증 플로우

```
┌─────────────────────────────────────────────────────────────┐
│                    항목 완성 점검                            │
├─────────────────────────────────────────────────────────────┤
│  사용자 입력 수신                                            │
│           ↓                                                 │
│  필수 필드 완성 여부 판단                                    │
│           ↓                                                 │
│  ┌───────┴───────┐                                         │
│  ↓               ↓                                         │
│ 완성           미완성                                       │
│  ↓               ↓                                         │
│ confirmed:    누락 필드 재질문                               │
│ true 설정     (confirmed: false 유지)                       │
└─────────────────────────────────────────────────────────────┘
                         ↓
┌─────────────────────────────────────────────────────────────┐
│                    단계 완성 점검                            │
├─────────────────────────────────────────────────────────────┤
│  현재 Step의 모든 항목 confirmed 확인                        │
│           ↓                                                 │
│  ┌───────┴───────┐                                         │
│  ↓               ↓                                         │
│ 모두 true      일부 false                                   │
│  ↓               ↓                                         │
│ 다음 Step     미완성 항목 재질문                             │
│ 이동          (현재 Step 유지)                              │
└─────────────────────────────────────────────────────────────┘
```

### 5.4 검증 예시

**Case 1: Step 0에서 직무 미입력**
```
[사용자] 오늘 날씨가 좋네요.

[AI] 반갑습니다! 그런데 포트폴리오 작성을 위해 
     본인의 희망 직무를 알려주셔야 해요.
     어떤 직무를 희망하시나요?
```

**Case 2: Step 4에서 일부 필드 누락**
```
[사용자] 프로젝트명은 folio4me이고, 기간은 20241201~20251218, 
        기술 스택은 Python, FastAPI입니다.

[AI] 입력된 내용:
     • 프로젝트명: folio4me
     • 기간: 2024.12.01 ~ 2025.12.18
     • 기술 스택: Python, FastAPI
     
     담당 직무와 관련 링크가 누락되었습니다.
     해당 정보를 추가로 입력해주세요.
     (관련 링크는 여러 개 입력 가능, 없으면 "없습니다"라고 입력)
```

### 5.5 Null 허용 규칙

- 사용자가 특정 필드 입력을 거부할 경우, 해당 필드는 `null` 값으로 저장
- `null` 값이 저장되어도 `confirmed: true`로 처리 가능 (의도적 거부로 간주)
- 거부 의사 표현 예시: "없습니다", "입력하지 않겠습니다", "패스할게요" 등

```
[사용자] 관련 링크는 없습니다.

[AI] 알겠습니다. 관련 링크는 비워두겠습니다.
     
     입력된 내용:
     • 프로젝트명: folio4me
     • 기간: 2024.12.01 ~ 2025.12.18
     • 담당 직무: 백엔드 개발, API 설계
     • 기술 스택: Python, FastAPI
     • 관련 링크: (없음)
```

### 5.6 렌더링 규칙

#### 5.6.1 필드 레벨 Null

- 특정 필드가 `null`인 경우, **해당 필드만** 화면에 표시하지 않음
- 예: 프로젝트의 "관련 링크"가 null → 프로젝트는 보이고, 관련 링크 필드만 안 보임

#### 5.6.2 항목/섹션 레벨 Null

- 항목 자체가 없음 (0개)인 경우, **해당 Step 섹션 전체**가 화면에 표시되지 않음
- 예: "이력 없습니다" → Work Experience 섹션 전체가 안 보임

```
┌─────────────────────────────────────────────────────────────┐
│  Null 렌더링 규칙                                            │
├─────────────────────────────────────────────────────────────┤
│  필드 레벨 Null     →  해당 필드만 렌더링 안 함               │
│  항목/섹션 레벨 Null →  해당 섹션 전체 렌더링 안 함           │
└─────────────────────────────────────────────────────────────┘
```
